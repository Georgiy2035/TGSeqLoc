# Абляции на V4RL: эталонная конфигурация и план

Документ фиксирует конфигурацию, на которой выполняются все абляции статьи, план абляций и их результаты.
Все абляции — на V4RL с обучением на V4RL. Результаты отсюда переносятся в таблицы статьи.

Эталон — конфигурация прогона `v4final-add-s42` от 2026-09-15 (коммиты 3501b42, 8a754f7) с одним изменением,
принятым 2026-09-15 до основной серии: **валидация — два блока вдоль маршрута** (раздел 1.1).
Любая абляция меняет **ровно один** фактор относительно эталона; всё остальное — как в разделе 1.
Конфиги абляций — `experiments/generators/setup_v4abl.py`, раннер — `experiments/runners/v4abl_run.sh`.

## 1. Эталонная конфигурация

### 1.1 Данные и протокол

| Параметр | Значение |
|---|---|
| Датасет | V4RL shopping_street_1: seq1 — база (7 494 кадра), seq2 — запросы (8 577 кадров) |
| Ground truth | `gt_shop_street_1.txt`, интервалы соответствий с интерполяцией (`interpolate_gt: true`), допуск 50 мс |
| Тест | хвост последовательности запросов (`test_ratio: 0.2`), целиком: **1 012** запросов |
| Валидация | **два блока** с центрами на 30 % и 60 % аннотированных запросов до теста (`split_guard: ground_truth_blocks`, `validation_centres: [0.3, 0.6]`), вместе 10 % этих запросов: **664** запроса (блоки 2042–2373 и 4036–4367) |
| Защита разбиения | части не делят кадры ground truth; приоритет у теста, затем у валидации — выбрасываются запросы обучения: обучение **4 759** (выброшено 1 223) |
| Почему блоки | R@5 модели без текста меняется вдоль маршрута от 1 % до 100 % на соседних сотнях запросов; прежняя валидация (один кусок из 387 запросов перед тестом) давала 41 % при 82 % на тесте и не различала эпохи. С блоками: без текста — вал 72.1 / тест 80.2, эталон — 92.5 / 92.4 |
| Позитивы обучения (аналог 10/25) | центральная половина интервала ground truth (`positive_interval_fraction: 0.5`); оценка — по полному интервалу |
| Метрики | R@1, R@5, R@10, R@25, R@100 (`top_k: 100`), точный поиск FAISS по косинусу по всей базе |

### 1.2 Пайплайн

| Этап | Значение |
|---|---|
| Граф сцены | Mask2Former Swin-L COCO panoptic (`tgseqloc/data/scene_graphs_m2f`), instance-маски с порогом 0.5, динамические классы отброшены на выходе детектора, рёбра — геометрические правила (in / standing on / beside / above / next to) |
| OCR | Qwen3-VL 4B (`qwen3_vl_4b.json`), уверенность не используется (порог 0.0) |
| Фильтр мусора | длина строки ≥ 3, строка не из одних цифр (`text_min_length: 3`, `text_drop_numeric: true`) |
| Сегментация динамики | YOLO11x-seg, порог уверенности 0.25, 13 классов (person, bicycle, car, motorcycle, bus, truck, train, backpack, handbag, suitcase, tv, laptop, cell phone) |
| Фильтр динамического текста | IoA рамки строки с маской динамики ≥ 0.5 → строка удаляется (`mask_ioa`, `threshold: 0.5`) |
| Привязка строки к объекту | `overlap_nearest`, k = 1: объект, чья рамка содержит центр строки, затем максимум IoU, затем ближайший центр |
| Энкодер строк | char n-grams 3–5, CRC32, 64d, L2-нормировка (`char_ngram`, `embedding_dim: 64`), без весов |
| Форма текста | слагаемое (`text_fusion: additive`): $\mathbf{c}_o \leftarrow \mathbf{c}_o + \sum_{t\in T_o} W\phi(s_t)$, W — линейный слой без смещения |

### 1.3 Модель

| Параметр | Значение |
|---|---|
| Графовый энкодер | GATv2, **1 слой × 4 головы**, hidden 256 |
| Эмбеддинги | класс вершины 64d, метка ребра 64d, геометрия ребра (10 признаков, нормировка по обучению) |
| Пулинг и выход | mean + max по вершинам-объектам → линейная проекция → **дескриптор 256**, L2-нормировка |
| Прочее | dropout 0.1, `text_dropout: 0`, `text_zero_init: false`, `descriptor_norm: none`, смещение проекции есть |

### 1.4 Обучение

| Параметр | Значение |
|---|---|
| Функция потерь | triplet, margin 0.3, 2 негатива на запрос |
| Негативы | эпохи 1–10 — случайные (`miner_warmup_epochs: 10`), далее — ближайшие (hard mining, глубина поиска 256) |
| Оптимизатор | AdamW, lr 3e-5, weight decay 1e-4, batch 8, клиппинг градиента 5.0 |
| Длительность | до 30 эпох, ранняя остановка по R@5 на валидации, patience 5 (отсчёт после прогрева) |
| Воспроизводимость | детерминированные CUDA-ядра, сид задаётся до создания модели; прогон `v4final-add-s42` побитно повторён на коде от 2026-09-15 (после выноса проверки графов из Trainer и добавления блочного разбиения) |

## 2. Протокол абляций

**Решение 2026-09-15: все абляции — один сид (42).** Ниже — исходное обоснование числа сидов; при одном сиде статистика только по блокам теста (21 блок по 50 запросов), разброс между сидами не оценивается.

**Сиды (исходный план).** На V4RL разброс между сидами велик: в прежнем протоколе (10 сидов, `docs/results/2026-09-14_training_and_text.md`, §1) sd R@5 у модели без текста ≈ 9 пунктов, у вариантов с текстом ≈ 1.5–3 пункта. Точный знаковый тест по 5 сидам не может дать p < 0.05 (минимум p = 0.0625), по 10 сидам — может (минимум p = 0.002).

- Все варианты — **5 сидов (42–46)**, одни и те же для всех вариантов: сравнения парные.
- Строки основных таблиц статьи (эталон, без текста, перемешанный текст, формы текста, OCR, фильтры) — **10 сидов (42–51)**.
- Отчёт: среднее ± sd по сидам; парная разница с вариантом-эталоном; p — знаковый перестановочный тест по 13 участкам теста (по 50 соседних запросов, попадания усреднены по сидам), 95 % ДИ — бутстрэп по тем же участкам; для 10-сидовых строк дополнительно точный знаковый тест по сидам.

**Эталон — один набор прогонов.** Эталонная строка считается один раз и используется во всех абляциях.

**Оценка затрат.** Сегодня три прогона V4RL шли параллельно и заняли около 20 минут, то есть ≈ 9 прогонов в час. План ниже — около 40 вариантов × 5 сидов ≈ 200 прогонов плюс ≈ 50 на расширение до 10 сидов, ≈ 28 часов GPU. Подготовка данных (маски, OCR других моделей, графы других генераторов) — отдельно.

## 5. Открытые вопросы до запуска

1. **Валидация.** В эталоне модель без текста даёт R@5 41 % на валидации и 82 % на тесте: после исключения пересечений в валидации остался трудный участок. Выбор эпохи по такой валидации может искажать сравнения. Варианты: оставить раннюю остановку, фиксировать число эпох или сменить участок валидации. Решить до основной серии.
2. **A5.** Какие генераторы графа входят в статью и откуда взяты графы Gemini и Grounding DINO (промпты, модели, дата).
3. **Число сидов.** Подтвердить схему 5 сидов для всех и 10 для строк основных таблиц.
4. **Статистика между таблицами.** Нужна ли поправка на множественные сравнения (много вариантов против одного эталона).
